## Local minified verification upgrade

On the fresh emulator, an existing local debug-signed releaseVerification **1.7.1 / 20** APK was
installed. A synthetic PDF was imported through DocumentsUI, processed with bundled Latin OCR,
saved to the private library, and confirmed present after a cold app restart. The candidate
releaseVerification **1.7.2 / 21** APK has the same public certificate SHA-256:
`5322fc417966b492abc3926526aafc81b39571b6875d193416ed0cb71e773fe7`.

`adb install -r` succeeded without uninstall/data clear. Package metadata changed from code 20
to 21 while `firstInstallTime` stayed unchanged. The saved one-page document and its original
import-date metadata remained visible after upgrade. Searching **SYNTHETIC** after upgrade returned the saved OCR text and page 1 of the existing
document. This confirms persisted OCR indexing and result navigation data survived this local update.

Android Settings App info displays **RME: Private PDF Scanner** after the update. At **320 dp
width / font scale 1.3**, the minified candidate's About dialog shows the full official title,
version 1.7.2 / build 21, attribution and both controls without clipped text in the inspected
screenshot. Compact navigation/home labels remain RME PDF Scanner. The APK was built from the
reviewed working tree (About revision `9bd43eb-dirty`); the hashes above identify those local
verification artifacts. Final owner-signed artifacts must be rebuilt from the approved commit.
The actual Android share sheet displays the full official name and unchanged Play application URL;
it was inspected without selecting a recipient or sending text. MainActivity's short label also
covers inbound app chooser entries. No app-created notification or shortcut labels were found
in maintained source; existing reminders are in-app UI.

This is supporting evidence from **local debug-signed, minified verification builds**. The old
APK was an existing local artifact; this run did not rebuild it from the v1.7.1 tag. It is not a
production Play/GitHub signer upgrade test and does not establish the full upgrade matrix for
folders, app-lock credentials, encrypted restores, deletion, export or Share-Safe. Those gates
remain in the owner checklist even where separate candidate instrumentation passes.
